Software Factory Map

A reusable way to take work from an idea to running software with AI agents, sized from a one-line bug fix to a multi-week effort. It starts from the NGC2 prototype runbook and follows the six stages of Anthropic's AI-native SDLC playbook.

This is a working sketch for discussion. Nothing here is built yet. Model names in the figures are today's defaults; each one comes from a single role table, so a swap is one edit.

Figure 1

Six stages, one loop

Each stage ends by committing a file, and that commit starts the next stage. A person signs off at every stage. The loop closes when monitoring or a lesson turns into new intent.

Figure 2

Three tracks, one factory

A quick triage picks the track. Smaller tracks run a lighter version of the same stages or skip one, so small work still lands as a reviewed merge with evidence.

Figure 3

The task loop inside Build and Test

Every plan task runs this loop. The review is a panel of reviewers, each looking for one kind of problem (Figure 4), and each writes its verdict on the first line of its review file. Tags name the role; the model comes from the role table.

Figure 4

The review panel

Each lens reviews the same change at the same time, using its own checklist from the project's REVIEW.md. The round ends only when every lens has reported. A blocker or major finding from any lens sends the task back for fixes. Maintainability findings on their own never block: they become follow-up tickets. A Fix runs correctness and security, a Feature adds maintainability, and an Epic runs all four, plus any lenses a project adds, such as UX or performance. Three lenses also read one of Matt Pocock's skills as guidance for their lens, never running it: correctness reads tdd, maintainability codebase-design, and spec compliance domain-modeling when the project keeps a CONTEXT.md or ADRs. Security reads none.

Open questions

Still to decide

  1. Track thresholds.

    Proposed in the design (section 8.3): a Fix is one session and one task; a Feature is up to about five tasks; anything with milestones or crossing repos is an Epic. Awaiting your review.

  2. Packaging.

    Proposed in the design (section 6.1): one plugin with a Claude Code manifest and a Codex manifest sharing one skills folder, as BSI's codex-plugin repo already does.

  3. Pilot project (deferred).

    Likely a new MACE plugin. Version 1 is set up and documented first.

  4. Hooks that enforce rules (parked).

    Which rules block outright and which ask you; Codex hooks cannot ask yet.
